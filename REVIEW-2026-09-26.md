### Deliberate behavior and limits

- No resampling/downmixing was introduced. Audio above 192 kHz or with more than
  two channels is rejected with instructions to use an audio editor.
- In-place validator WAV conversion retains a hidden `.a8-original-…` sibling
  backup; errors report its location when recovery requires assistance.
- ZIP import accepts a flat one-preset archive with up to 64 WAV entries. Conflicting
  audio is rejected rather than silently renamed, since archived preset references
  must remain consistent.
- Move in a filtered list means the adjacent numbered preset slot, not the
  adjacent visible row. Save follows the moved preset.
- Stereo list edits keep each side's file/selector. An unpaired mono assignment
  or paste into an existing pair deliberately duplicates that source on both
  sides. An occupied independent next channel is not commandeered automatically.
- Missing paired sources are reported by Copy/Continue/Explode rather than
  multiplying incomplete pairs. Insert refuses to discard an occupied eighth
  zone. Explode covers the final remainder instead of dropping trailing frames.
- Same-path sample reload may stop audition while buffers are invalidated; it
  must not continue playing stale data.
- The file-browser importer uses the same checked, source-preserving service as
  zone assignment. Missing-file Locate uses no-overwrite copying too.
- Final Debug-log review also found channel eight trying to wrap invalid optional
  partner trees. It now explicitly releases those bindings; the stereo test checks
  detachment and correct rebinding when returning to an earlier channel.

## Assimil8or capability comparison

Principal preset/channel/zone parameters are represented, as are MIDI Indexed KZ,
Index Base Key and the expanded ±48-semitone wheel range. The release page lists
firmware 3.04 while its written history stops at 3.03, so this is not a complete
latest-firmware parity certification. Phase Mod **Source CV gain** remains
editable here although Rossum identifies it as unused in real-time playback;
preserve legacy data but consider marking that amount field legacy/unused.
[Official downloads and release notes](https://www.rossum-electro.com/pages/downloads)

Useful unexposed configuration families are per-folder preset increment/decrement/
reset CV assignments, hardware Preferences (gate delay, display settings,
auto-audition and load-folder warning), and Sampling Setup/monitoring/sound-on-sound.
These are not simply additional preset knobs. Hardware-written example files are
needed to establish their schemas before adding safe editors; do not invent YAML
keys. [Official 2.0 feature guide](https://cdn.shopify.com/s/files/1/0277/4548/4865/files/A8_update_manual_061820.pdf?v=1785520029)

Loop and Loop/Release differ on gate release, and reverse changes the hardware's
data/marker orientation. The precise later-loop traversal described by the user
was not found explicitly in the manual; the new source-coordinate stripes use
that observation rather than claiming a full playback simulation.
[Official manual](https://cdn.shopify.com/s/files/1/0277/4548/4865/files/Assimil8or_man_040618-2.pdf?v=1785520023)

## WAV-marker import proposal — not implemented

The pinned JUCE reader already exposes `cue ` points, labeled cue regions and
`smpl` loop metadata. The application currently does not consume them. Four app
boundaries are roles, not a limit on how many imported cues can be presented.

An **Import WAV markers…** dialog should:

1. Suggest mappings for explicit labels such as Sample Start/End and Loop Start/End.
2. Offer a single valid forward `smpl` loop as the loop pair.
3. Show all remaining cues/loops by label and position, allowing the user to select
   each of the four roles. Never assume the first four cues have these meanings.
4. Keep unspecified boundaries unchanged, with an explicit whole-file Sample
   option. Preview and confirm before changing the zone; never modify the WAV.
5. Validate file bounds, ordering and minimum loop length. Warn about backward/
   alternating loops, repeat counts and unsupported fractional semantics.

`smpl` loop end is **inclusive**, requiring `end + 1` for this app's exclusive
boundary. Generic cue positions should not receive that adjustment; a cue region
ends at its start plus length. Labels/regions must be linked by cue identifier,
not their list order. [Microsoft WAV reader](https://github.com/microsoft/DirectXTK/blob/main/Audio/WAVFileReader.cpp)
and [IBM/Microsoft RIFF specification](https://www.mmsp.ece.mcgill.ca/Documents/AudioFormats/WAVE/Docs/riffmci.pdf)

A separate future **Create zones from consecutive markers** operation could use
more of a sliced WAV's cues, subject to the eight-zone limit. A representative WAV
exported by the user's audio editor would be the best next import test fixture.
